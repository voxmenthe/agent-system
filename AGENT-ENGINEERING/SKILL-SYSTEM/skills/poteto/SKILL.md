# Poteto

Carry the owner's software outcome through a useful feature slice and honest
PR handoff. The parent selects and sequences work; stage owners retain their
substance. Use one implementation writer and a fresh native non-author review
context. No provider framework, recursive delegation, scheduler, or merge bot.

## Entry and composition

Resolve and briefly state the accepted outcome/criteria, preserved behavior,
mode, write scope, human-reserved choices, total bounds, Git/PR grant and exact
destination, and `pr_explanations: off | show-me-clearly` (default off).
Reuse existing authorization. Ordinary means and transitions need no renewed
approval; missing consequential direction or required authority does.

| Mode | Bound |
| --- | --- |
| Poteto | One coherent work unit by default, through authorized PR handoff |
| Bounded autonomous | Finite total work-unit or measurable compute/token budget settled at entry; select successive useful gaps |
| Resume | Reconcile the saved run before new effects; retain spent bounds and owner steering |

One writer is fixed. Default backlog limit is two open run-owned PRs; default
no-progress repair allowance is two attempts. Stricter accepted limits win.
Charge repairs and child work to total usage; never reset counts on resume.
If tokens cannot be measured, say so and settle an enforceable work-unit bound
instead. No work is required just to reach a count or spend a budget.

**Explicit-only leaves remain explicit-only.** Inspect the actual host inventory
and exact source paths before routing. This entry does not make an omitted leaf
eligible. The verification setup, upkeep, and acceptance owners may be selected
implicitly for a material capability or acceptance gap; adequate recipes and
evidence stay on the direct path. `map-change` may resolve uncertain change
impact, and `architecture-plan` an unsettled consequential boundary decision;
reuse existing maps and settled designs. For the remaining explicit-only owners, the
one-time initial request can be:

```text
Use $poteto with $implement-change
to add offline capture inspection. Preserve normal archive output.
You may commit and create/update its PR to the specified repository/base.
```

The actual request supplies the destination; the example grants none. Add
`$show-me-clearly` when requesting a PR explanation. `frame-change` and
`diff-review` may route under their existing implicit eligibility. Mentions
permit consideration, not mandatory execution of every skill. Missing required
eligibility leaves that route incomplete: name the missing leaf and usable
entry, continue independent authorized preparation, and do not silently use
an upstream namesake or insert hidden slash-command chains.

For a standalone trivial edit, use the direct read/edit/check path without
new run state or fan-out. A tiny step inside an existing PR run retains that
run's review, evidence, and handoff obligations.

## Owners and handoffs

Read each eligible owner's actual skill when its trigger applies. Do not copy
its domain workflow into this coordinator or install missing dependencies.

| Need | Owner | Handoff / skip |
| --- | --- | --- |
| Sufficiently understood nontrivial outcome | `frame-change` | Outcome, concrete use, criteria, preserved contracts, authority; unsettled product intent returns to owner |
| Uncertain impact of an authorized brownfield change | `map-change` | Reuse current source/caller/test/history evidence; skip an already-mapped boundary |
| Unsettled consequential boundary decision | `architecture-plan` | Outside-in contract and first check; skip established patterns, settled designs and artificial alternatives |
| Missing real-product drive/proof capability | `create-verification-skill` | Proved target-local recipe; reuse adequate existing instructions |
| One settled vertical slice | `implement-change` | Actual integrated feature diff, boundary checks and builder evidence, not self-approval |
| Affected existing verification instructions | `maintain-verification-skill` | Owned corrections re-driven, or clean/blocked coverage; skip unaffected recipes |
| Defects in frozen candidate | fresh `diff-review` | Distinct findings and exact changed-path coverage |
| Acceptance against the brief | fresh `verify-change` | Criterion-by-criterion proof and Accept / Revise / Return to design / Restart |
| Requested explanation | `show-me-clearly` | Current saved walkthrough, own checker, reviewer-accessible link |
| Checkpoints and publication | parent Git/forge edge | Only the current scoped grant; no leaf acquires publication authority |

Assessment must establish current versus intended behavior, a real usage
scenario, acceptance including negative/preserved cases, the chosen feature
slice, and any material design choice. Keep this in the existing brief/run
note, not three new stage documents. Record:

`TRACE / FIRST UNIT / WRITE SEAM / FIRST CHECK / EXPAND ONLY WHEN`

## Execute one unit, then reassess

1. **Assess the next useful gap.** Use criteria, current evidence, rejected
   directions, dependencies, backlog, and remaining bounds. Explain its objective
   relevance. Stop as soon as completion is supported. Only the owner changes
   accepted objectives/rubrics.
2. **Establish proof before building.** Drive an existing public path and settle
   how the new/changed workflow will be falsified. A new feature absent at
   baseline is expected, not a product bug. Use setup only for an operating
   capability gap; unbuilt behavior stays explicitly unexercised.
3. **Implement the settled slice.** One writer uses a task-owned branch/checkout,
   preserves unrelated work, and checks the integrated new and retained paths.
   For bugs, retain failing-before/passing-after evidence unless genuinely
   impossible, with the reason. Route affected recipe upkeep before freezing.
4. **Freeze and independently challenge.** Commit only within Git authority;
   pin complete base/head IDs and scope. Without commit authority, preserve the
   inspectable local diff but leave frozen-candidate/PR readiness incomplete.
   Dispatch fresh native review/verification as described below. Repairs return
   to the writer; wrong premises return to assessment. Any source, requirement,
   runtime, or relevant recipe change invalidates its readiness and receives
   fresh affected checks and a current final disposition.
5. **Deliver at the parent's authorized edge.** Create/update the actual PR only
   under the scoped grant; query its repository/base/head after the write and
   match candidate evidence. A request sent or unpublished patch is not a PR.
   Required proof stays accessible with explanations off. If requested, a
   missing/stale explanation makes documentation handoff incomplete, not code
   incorrect and not the package complete. A committed proof document names
   the tested source revision separately from the final documentation head;
   recheck source equivalence without a self-referential hash-update loop.
   Use the repository's PR template and retain its required fields. Otherwise
   explain the outcome and smallest useful mechanism, link actual source-bound
   checks/results and limitations, and state affected consumers, material
   break/change blast radius, and reversibility of effects. Keep the PR body
   current with the final candidate; code rollback does not undo every effect.
6. **Checkpoint and choose.** Record keep/reject/revise, evidence, dependencies,
   spent/remaining limits, and next action in the run note. Owner acceptance is
   separate from readiness, and a PR proves neither merge nor deployment.

Do not pause at routine stage boundaries. Stop for cancellation, completion,
exhausted bounds, backlog limit, repeated no-progress, unavailable required
proof/authority, or a human-reserved choice. Independent authorized work may
proceed around a blocked unit, but its existence does not enlarge scope.

## Independent verification and real-surface proof

The parent dispatches one fresh non-author native context with the accepted
contract, complete base/head IDs, scope, recipe and raw evidence pointers.
Do not pass the builder's conclusion as an instruction. The same reviewer may
perform `diff-review` then `verify-change`, keeping their outputs distinct.
Authorize only read-only source inspection and expressly disposable verification
resources. It cannot edit product/recipe/expectations, spawn children, select
providers or next work, approve a PR, or publish. Join its result before delivery.
If the host cannot supply this context, prepare the candidate and report the
independent-verification/PR-readiness gap; self-review is not a substitute here.

Proof exercises the requested public path, preserved behavior, and a negative
case that could expose a partial/wrong feature despite old tests passing.
Bind evidence to the actual launched binary/module/process and material
resources. Wrong instance/path or unavailable prerequisites remain unverified.
Health-check before driving and after surprising failures; reset or relaunch
owned state if health cannot establish readiness. Worktrees do not isolate
ports, profiles, databases, caches, or workers. Use owned disposable resources
or declared serial access; never reset the owner's main session. Cleanup failed
and successful attempts, releasing only owned resources while retaining proof.

## Continuity, steering, and recovery

For nontrivial work, use one task-local `RUN.md`. Read
[run-note guidance](references/run-note.md) on first checkpoint and resume.
Default location, when no task workspace exists, is
`<authorized-task-root>/.poteto/<run-slug>/RUN.md`; exclude local state through
existing ignore conventions or the repository's local exclude file. Never save
run state in the installed skill. Existing host/test/Git/PR records own evidence.

Status reports do not cancel the objective. Answer ready results, current useful
work, blockers/bounds, and links, then continue. Owner corrections revise the
affected contract and invalidate affected evidence while preserving independent
work. Preserve the last complete checkpoint, save the frontier and read it back
before relying on it. An interrupted note write requires reconciliation with
authoritative evidence, not reconstructed approval or invented checks.

Native context compaction may continue an active session. After shutdown,
explicit resume first establishes that the previous executor ended or handed
off, then reconciles the actual checkout, forge and runtime under remaining
bounds. If ownership is uncertain, do not mutate that run. No concurrent resume
or unattended restart is supported; a timestamp is not a lease.

Before retrying an interrupted PR write, query the exact repository/head branch
and destination: reuse the matching PR or stop if the effect remains uncertain.
Cancellation stops new effects, settles/records in-flight writes, joins/stops
owned children, and cleans only owned resources. Do not delete published work.

Keep units independently reviewable; declare unavoidable dependencies. Rejection
stops that direction and invalidates descendants, not useful independent work.
Preserve checkpoints and rebuild/reapply needed work on a clean owned branch
using authorized ordinary Git. Recheck recovered candidates and explanations.
No silent history rewrite, force-push, automatic PR closure, or physical deletion.

At handoff, record decisive observations in the existing evaluation/run location:
task and source/host → evidence → owner burden/defect → cause or hypothesis →
smallest correction/recheck → full-plan implication. Unknown measurements stay
unknown. Change coordinator/verifier guidance between identified runs, never
by letting an active run redefine its own controls.
