# Web Research Then Plan

Turn current source evidence into an actionable plan for the user's project,
not a generic topic summary or an implementation campaign.

## Establish the artifact

Preserve the requested directory, filename, scope, and reference plan. Read the
relevant local instructions and project context before choosing a plan shape.
When an applicable plan index exists, read it and the nearest relevant active
plan to understand conventions. Read other status/history files only when they
affect the requested work; no particular project framework is required.

Resolve unspecified placement from the project's existing convention and the
user's scope. If no index exists, still create the requested Markdown plan and
report that no index was updated. Do not create an index or new planning system
solely to satisfy this skill.

## Research the decisions

Start with authoritative sources for the requested topic and version: official
documentation, original papers, model cards, or the maintained repository. Use
focused follow-ups for limitations, compatibility, and the capabilities the
plan actually depends on. Stop when the consequential decisions are supported;
respect the user's research budget rather than imposing a fixed query count.

Open the sources supporting material claims. Record their direct URLs and
relevant version/date context. Separate verified capabilities from project
inferences and unknowns; a proposed integration is not a demonstrated one.
If web access fails, state what could not be checked. A clearly marked partial
draft can preserve useful local work, but do not claim the research requirement
is complete or invent facts to fill the gap.

## Write and connect the plan

Match the project's useful conventions, keeping the plan self-contained. Include
the context, concise cited findings, scope/non-goals, concrete work steps and
dependencies, acceptance evidence, and material open questions. Link each
research-derived claim to its source near the claim; distinguish recommendations
from source statements. Size phases to the actual task, not a template quota.

If an applicable existing index is in scope, add the plan under the appropriate
section using its current format. Preserve unrelated entries and avoid duplicate
links. If several indexes are plausible, use the one owning the requested plan
directory; ask only if the remaining ambiguity would materially change scope.

Read back the plan and any index edit. Check local links, cited support for
load-bearing decisions, path conventions, and consistency between steps and
validation. Report the plan path, any index update, key findings, and unresolved
research. Writing this plan does not authorize implementation, dependency
installation, commits, or publication.
