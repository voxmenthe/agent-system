# Source seeds and role routing for `/agents`

Seeds are **starting points, not an allowlist and not blanket endorsements**.
Their purpose is to expose useful mechanisms, artifacts, and adjacent
conversations. Promote any source only for the contribution visible in the
fetched post/thread.

Maintain a handle as a durable seed only after a bounded own-feed check finds at
least two distinct substantive root conversations. Each root should pass the
normal two-of-four actionability gate: procedure/config, measurement,
failure/boundary, or inspectable artifact. Product cadence, fame, and several
nodes from one self-thread do not establish recurrence.

## Dynamic source roles

For each promising root, look for:

1. **Builder report** - procedure/config plus observed outcome
2. **Maintainer/repository evidence** - implementation or benchmark boundary
3. **User replication** - independent setup and result
4. **Independent critique** - confound, shortcut, task mismatch, failure mode
5. **Correction/boundary voice** - version, cost, permissions, reliability
6. **Product announcement** - discovery only until technical detail appears

Count a self-thread as one source chain. A reply from another account is not
independent evidence merely because the handle differs: check whether it adds
an attempt, artifact, measurement, or distinct technical reasoning.

## High-signal traits

- commands, configuration, prompt/spec, or reproducible procedure
- named model/version, harness/tools, and task/eval
- measured turns, defects, pass rate, latency, tokens, or cost
- actual trace, issue, repository, benchmark, or inspectable artifact
- failure mode and operating boundary
- comparison against a baseline
- independent reproduction or concrete counterexample
- maintainer correction that changes applicability

## Low-signal traits

- “this changes everything” without a procedure
- screenshot-only demo with no task or failure surface
- model ranking without harness/eval context
- product availability announcement treated as practice evidence
- praise-heavy replies
- benchmark score without contamination/cheating/setup discussion
- repeated downstream summaries from one builder claim
