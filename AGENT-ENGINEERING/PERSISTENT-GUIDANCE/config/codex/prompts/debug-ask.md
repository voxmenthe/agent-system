# Debug: Ask Sharp Questions (Break the Loop)

When stuck, ask questions that would *decide* the next step.

## Output
Provide:
1) **Three crisp questions** whose answers would eliminate entire classes of causes (not implementation suggestions).
2) For each question, the **cheapest way to answer it** (instrumentation, snapshot, trace filter, probe).
3) The **single next action** that yields the most information per minute.
4) A 1‑paragraph “rubber duck” explanation—state what you *know*, what you *assume*, and what would change your mind.

*No code changes until at least one question is answered.*
